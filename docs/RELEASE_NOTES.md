## Не выкачено

Серия PRESET (`docs/STRATEGY_PRESETS_PLAN.md`). Выкладка — только после PRESET-09a.

### Переименованы параметры стратегии (PRESET-01)

- `swing_low_h1_n` → `swing_low_wave_n`, `trail_m15_n` → `trail_ripple_n`. Сохранённые
  параметры запуска со старыми именами агент переводит сам.
- **После обновления перезагрузите вкладку Strategy.** Вкладка, открытая до выкладки,
  получит на Start `422 "parameter '…' was renamed to '…'; reload the page"`;
  несохранённый черновик этой вкладки будет потерян (план §4.6, G2).

### Строже проверка параметров Start (PRESET-04a)

Касается обоих маршрутов: `POST /trading/start/` и `POST /trading/commands/` с `type: "start"`.

- **Типы.** Целое поле, включая элементы `ema_tide_periods`, принимает только JSON integer:
  `true`, `"5"` и `5.0` теперь `422 int_type`. Decimal-поле — JSON number или строка, но не
  `true`/`null`.
- **Числовой домен.** Число — не больше 64 значащих цифр и порядок в пределах ±64 (по
  значению: `"1e64"` и `"1"` с 64 нулями допустимы, ноль — всегда); иначе
  `422 too_large` на поле.
- **Неподдерживаемое значение** поля со списком (например, `ripple_interval: "1M"`) —
  `422 unsupported_value` на поле, в том числе когда каталог опубликован без enum
  (раньше в таком случае был `503`).
- **Межполевые правила считаются точно**, без округления: например,
  `stochastic_k_period = 10^28` при `kline_window = 10^28` теперь отклоняется.
- **Формат ошибки.** `loc` ошибки поля — `["body", "params", <поле>, …]` (раньше
  `[<поле>]`); межполевое правило и неизвестный ключ — по-прежнему `["body", "params"]`.
- **Секция `execution` проверяется так же** (компилятор общий): `enabled` — только
  `true`/`false` (не `"true"` и не `1`), целые — только JSON integer, числа — в том же
  домене; `loc` — `["body", "execution", <поле>]`.

Для текущего UI почти ничего не меняется: целые он отправляет числами, decimal — строкой,
секцию `execution` не отправляет вовсе. Одно исключение: decimal уходит строкой как
введён, поэтому, например, `tp_pct = 1e70` раньше доходило до агента, а теперь получает
`too_large`. Остальное касается внешних клиентов API, в первую очередь тех, кто включает
реальное исполнение через `execution`.

Перед выкладкой (G1, план §7.1): `desired.params` и `desired.execution` с прода должны
проходить новые проверки.

### Наборы настроек и списки выбора (PRESET-05a, 05b, 06)

- Новые API: `GET/POST/PUT/DELETE /trading/strategies/{strategy}/presets/` (наборы,
  встроенные `Default` и `Fast` приходят от агента и только читаются) и
  `GET /trading/strategies/{strategy}/options/`, `PUT …/options/{field}` (списки
  выбора quote asset и трёх интервалов). Только для superuser.
- **Start проверяет списки:** значение поля со списком, в том числе дефолт, если поле
  не передано, должно быть в списке — иначе `422 option_value` на поле. Начальные
  списки — T2 (`USDT`/`USDC`, интервалы от `1w` до `1m`).
- `NaN` в `symbols` или вместо `payload` команды теперь `422`, а не `500`.

### Выкладка закрывает Start на время замены агента (PRESET-09a)

- Пока идёт выкладка (обычно меньше минуты), Start по обоим маршрутам отвечает
  `503 "starting is closed for maintenance"`; Stop и остальное работают. Если выкладка
  упала, Start остаётся закрытым до решения человека (docs/DEPLOY.md §2).
- Выкладка не останавливает идущую стратегию: новый агент восстанавливает её из
  снапшота. Если после выкладки торговли быть не должно — сначала Stop (docs/DEPLOY.md §6).
