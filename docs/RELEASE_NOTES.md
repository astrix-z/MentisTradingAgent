# Release notes

Заметки для людей, которые пользуются UI и API стенда. Записи о ещё не выкаченных
изменениях копятся в разделе «Не выкачено»; при выкладке раздел получает ревизию и дату.
Корневой `release-notes.md` — заметки шаблона FastAPI, к проекту не относится.

## Не выкачено

Серия PRESET (`docs/STRATEGY_PRESETS_PLAN.md`). Выкладка — только после PRESET-09a.

### Переименованы параметры стратегии (PRESET-01)

- `swing_low_h1_n` → `swing_low_wave_n`, `trail_m15_n` → `trail_ripple_n`. Сохранённые
  параметры запуска со старыми именами агент переводит сам.
- **После обновления перезагрузите вкладку Strategy.** Вкладка, открытая до выкладки,
  получит на Start `422 "parameter '…' was renamed to '…'; reload the page"`;
  несохранённый черновик этой вкладки будет потерян (план §4.6, G2).

### Таймфреймы: D1 и W1, правило «tide > wave > ripple» (PRESET-02, PRESET-03)

- Интервалы `1d` (D1) и `1w` (W1) поддерживаются во всех трёх ТФ; границы дневных и
  недельных баров — как у Binance (неделя с понедельника 00:00 UTC).
- Правило соотношения ТФ `16:4:1` (tide = 4 × wave = 16 × ripple) заменено на строгий
  порядок `tide > wave > ripple`. Всё, что проходило раньше, проходит и теперь; новые
  сочетания (например, `1h / 15m / 5m`, `12h / 4h / 1h`) стали допустимы.

### Строже проверка параметров Start (PRESET-04a)

Касается обоих маршрутов: `POST /trading/start/` и `POST /trading/commands/` с `type: "start"`.

- **Типы.** Целое поле, включая элементы `ema_tide_periods`, принимает только JSON integer:
  `true`, `"5"` и `5.0` теперь `422 int_type`. Decimal-поле — JSON number или строка, но не
  `true`/`null`.
- **Числовой домен.** Число — не больше 64 значащих цифр и порядок в пределах ±64 (по
  значению: `"1e64"` и `"1"` с 64 нулями допустимы, ноль — всегда); иначе
  `422 too_large` на поле.
- **Неподдерживаемое значение** поля со списком (например, `ripple_interval: "1M"`) —
  `422 unsupported_value` на поле, в том числе когда каталог опубликован без enum
  (раньше в таком случае был `503`).
- **Межполевые правила считаются точно**, без округления: например,
  `stochastic_k_period = 10^28` при `kline_window = 10^28` теперь отклоняется.
- **Формат ошибки.** `loc` ошибки поля — `["body", "params", <поле>, …]` (раньше
  `[<поле>]`); межполевое правило и неизвестный ключ — по-прежнему `["body", "params"]`.
- **Секция `execution` проверяется так же** (компилятор общий): `enabled` — только
  `true`/`false` (не `"true"` и не `1`), целые — только JSON integer, числа — в том же
  домене; `loc` — `["body", "execution", <поле>]`.

Для текущего UI почти ничего не меняется: целые он отправляет числами, decimal — строкой,
секцию `execution` не отправляет вовсе. Одно исключение: decimal уходит строкой как
введён, поэтому, например, `tp_pct = 1e70` раньше доходило до агента, а теперь получает
`too_large`. Остальное касается внешних клиентов API, в первую очередь тех, кто включает
реальное исполнение через `execution`.

Перед выкладкой (G1, план §7.1): `desired.params` и `desired.execution` с прода должны
проходить новые проверки.

### Наборы настроек и списки выбора (PRESET-05a, 05b, 06)

- Новые API: `GET/POST/PUT/DELETE /trading/strategies/{strategy}/presets/` (наборы,
  встроенные `Default` и `Fast` приходят от агента и только читаются) и
  `GET /trading/strategies/{strategy}/options/`, `PUT …/options/{field}` (списки
  выбора quote asset и трёх интервалов). Только для superuser.
- **Start проверяет списки:** значение поля со списком, в том числе дефолт, если поле
  не передано, должно быть в списке — иначе `422 option_value` на поле. Начальные
  списки — T2 (`USDT`/`USDC`, интервалы от `1w` до `1m`).
- `NaN` в `symbols` или вместо `payload` команды теперь `422`, а не `500`.

### Встроенные наборы `Default` и `Fast` (PRESET-04)

- Агент публикует в каталоге два набора: `Default` (текущие значения по умолчанию) и
  `Fast` — ТФ `1h / 15m / 5m`, `tp_pct 5`, `trail_cap_pct 1`, `max_hold_hours 4`,
  `signal_validity_minutes 5`, остальное как в `Default`. Backend переносит их в БД при
  чтении списка наборов; править и удалять их нельзя.

### Страница Strategy: наборы, списки, проверка на лету (PRESET-07, PRESET-08)

- **Набор** выбирается над формой: встроенные первыми. Выбор заменяет все параметры
  формы. После правки поля рядом с именем — «(modified)», у набора, который сейчас не
  пройдёт Start, — «(invalid)». **Save as…** сохраняет форму под новым именем,
  **Update** и **Delete** — только для своих наборов. Без сохранённых параметров запуска
  форма открывается с `Default`.
- Quote asset и три ТФ выбираются из списка; ТФ показаны как `W1, D1, H12 … M1`.
  Значение, которого агент не поддерживает, в списке видно, но недоступно.
- `EMA tide periods` — три поля вместо текста через запятую.
- Ошибки видны сразу при вводе; Start недоступен, пока форма не проходит проверку.
  Проверка та же, что у backend, включая точную арифметику межполевых правил.
- Под каждым ТФ — нужная история (`kline_window × ТФ`); больше года — жёлтое
  предупреждение без блокировки (например, D1 и W1 при `kline_window = 1000`).
- Блок **Option lists** (свёрнут): списки значений для quote asset и трёх ТФ.
  Ввод `H1` сохраняется как `1h`, `H1` рядом с `1h` — дубликат; значение, которого агент
  не знает (`custom`, `1M`), сохраняется с пометкой и в форме не выбирается. Если
  убрать значение, которое использует набор, страница предупредит, и набор станет
  «(invalid)».
- Если во время правки выкатили агента с другой схемой, черновик сохраняется (старые
  имена переносятся), над формой — предупреждение.

### Выкладка закрывает Start на время замены агента (PRESET-09a)

- Пока идёт выкладка (обычно меньше минуты), Start по обоим маршрутам отвечает
  `503 "starting is closed for maintenance"`; Stop и остальное работают. Если выкладка
  упала, Start остаётся закрытым до решения человека (docs/DEPLOY.md §2).
- Выкладка не останавливает идущую стратегию: новый агент восстанавливает её из
  снапшота. Если после выкладки торговли быть не должно — сначала Stop (docs/DEPLOY.md §6).

### Позиции по сигналам закрываются по первому пересечению (ClickUp 869f6m7vn)

- Раньше позиция на странице Positions закрывалась, только когда её кто-то
  открывал, и по цене этого момента: SENTUSDT пересёк стоп в 14:48 UTC, а записан
  закрытым в 15:14 на 1.7 % ниже стопа. Теперь агент сам следит за каждым ENTRY
  по закрытым 1m-свечам и публикует EXIT: время — минута первого пересечения,
  цена — уровень стопа или тейка, при гэпе — открытие этой минуты; минута,
  задевшая оба уровня, считается стопом.
- Закрытие при просмотре осталось запасным путём на случай потерянного EXIT; EXIT,
  пришедший позже, исправляет такое закрытие. Уже закрытые позиции не
  пересчитываются.
- Без реального исполнения стратегия теперь знает о своих позициях по сигналам
  (ClickUp 869f6m7vg): пока ENTRY по символу не закрыт пересечением, новых ENTRY по
  нему нет; после закрытия идёт `cooldown_minutes` от минуты пересечения. После
  рестарта или Start это восстанавливается. С включённым исполнением, как и раньше,
  в счёт идут только реальные позиции.

### Откат на ревизию до серии (PRESET-09b)

- Откат — только по docs/DEPLOY.md §6. На ревизии до серии (`T0`) снова действует
  `16:4:1` и старые имена параметров: `Default` проходит, `Fast` получает `422`.
- `alembic downgrade` до `T0` удаляет таблицы наборов и списков: **сохранённые
  пользователем наборы и правки списков пропадают**. Вернуть их можно только из
  `pre-deploy-app-*.dump` той выкладки (docs/DEPLOY.md §5).
- БД агента не откатывается: таблицы исполнения (серия EXEC) остаются, агент `T0` их не
  трогает, при повторной выкладке новый агент продолжает с той же ревизии миграций.
