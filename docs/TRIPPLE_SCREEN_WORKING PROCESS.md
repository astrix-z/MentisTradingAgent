 Собрал полную картину. Вот как ведёт себя TripleScreen после старта.
                                                                   
  Файлы стратегии
                                                                   
  agent/agent/strategies/tripple_screen/: strategy.py (528 строк,
  основная логика), indicators.py (математика индикаторов),
  settings.py (параметры), schema.py (ограничения для UI).
                                                                   
  Три «экрана» (Triple Screen — классика Элдера, адаптированная)
                                                                   
  Работают на трёх таймфреймах с жёстко навязанным соотношением
  16:4:1 (settings.py:91): tide (прилив, по умолчанию 4h), wave
  (волна, 1h), ripple (рябь, 15m).
                                                                   
  1. Tide — экран тренда (_tide, strategy.py:449-490)
  Тройной EMA по close, периоды (5, 13, 34) по умолчанию.
  Bullish-тренд признаётся, только если ВСЕ пять условий истинны:
  быстрая EMA растёт, средняя растёт, медленная растёт, быстрая > средней, последний close > медленной EMA. Если хоть одно ложно — 
  тренда нет, и весь сигнал глушится на этом этапе
  (strategy.py:370-371) — дальше даже не считается.
                                                                   
  2. Wave — экран осциллятора (_wave, strategy.py:498-527)
  Stochastic %K(5)/%D(3)/slowD(3) + Force Index Элдера (EMA(2) от
  (close[i]-close[i-1])*volume[i]). Разворот вверх (pullback_up)
  требует одновременно:
  - %K вышел из зоны перепроданности (был <20, стал ≥20),
  - %K пересёк %D снизу вверх,
  - Force Index пересёк ноль снизу вверх.
                                                                   
  3. Ripple — экран входа (_decide, strategy.py:369-378)
  Просто: close последней закрытой 15м-свечи пробивает high
  предыдущей 15м-свечи. 
  
  Логика гейтинга сигнала
                                                                   
  Порядок проверок (первая сработавшая причина блокировки
  становится reason): нет тренда → нет пуллбэка (wave) → нет пробоя
  (ripple) → уже есть позиция по символу → кулдаун (60 мин после
  закрытия) → эпоха уже отработана. Если всё пройдено —
  type="ENTRY", иначе type="HOLD" с причиной.
                                                                   
  Для ENTRY считаются: стоп (минимум low последних 2 wave-свечей
  минус 0.1%), тейк (+10% от входа), срок действия сигнала (15
  минут).
                                                                   
  Что происходит на каждой WS-свече (_on_kline,
  strategy.py:178-191)
                                                                   
  Прилетает каждое сообщение — и формирующаяся, и закрытая свеча. Цена (_last_price) обновляется всегда, даже на неполной свече.
  Вся логика ниже — только для закрытых баров. Только закрытие ripple-бара (15m) реально запускает пересчёт (_evaluate) — закрытия tide/wave просто обновляют скользящие окна, но сами по себе решение не триггерят.
                                                                   
  Важно: стратегия сама ордера не выставляет. Это подтверждает
  докстринг: sizing, order type and protection are downstream
  concerns — она только эмитит Signal (ENTRY/EXIT/HOLD) через
  services.emit(), который в движке публикует его в Redis-канал
  agent:events. Что дальше исполняет ордер — отдельный (видимо, ещё
  не реализованный или отдельный) компонент.
